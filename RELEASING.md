# Releasing Symposium for Android

Official releases are built only by `.github/workflows/release.yml` from pushed
SemVer tags without a leading `v`, such as `0.3.4` or `0.3.4-rc.1`. There is no
manual workflow path that can publish a release from an arbitrary branch.

## Repository setup

Before releasing, configure GitHub with:

- a protected `main` branch;
- the `Test and build` CI job as a required status check;
- approval requirements appropriate for changes to workflows and signing code;
- immutable releases enabled in repository settings;
- GitHub Private Vulnerability Reporting enabled;
- the release signing and optional telemetry secrets listed below.

The release job uses only `contents: write`, `id-token: write`, and
`attestations: write`. Pull-request CI has `contents: read` and receives no
release secrets.

## Prepare the release

1. Confirm that the intended `symposium-relay` release exists, is published and
   immutable, and contains the Linux amd64 binary, `SHA256SUMS`, CycloneDX SBOM,
   SLSA provenance, and CycloneDX attestation.
2. Update and verify the Android relay lock:

   ```bash
   scripts/update-relay-lock.sh 0.3.4
   scripts/fetch-relay.sh
   scripts/verify-relay-provenance.sh
   ```

3. Update `VERSION_NAME` and monotonically increase `VERSION_CODE` in
   `version.properties`. Android and relay versions are independent.
4. Open a pull request. Review the relay lock, dependency verification metadata,
   workflows, and application changes. Wait for the required `Test and build`
   check and any project review requirements.
5. Merge the approved pull request to protected `main`.

## Publish

Create the Android tag on the exact merged commit and push it. A signed annotated
tag is recommended:

```bash
git switch main
git pull --ff-only
git tag -s 0.3.4 -m "Symposium 0.3.4"
git push origin 0.3.4
```

The release workflow rejects a malformed tag, a tag whose commit is not contained
in `main`, or a tag that differs from the authoritative Android `versionName`.
It then performs this sequence:

```text
immutable relay release
        ↓
locked relay checksum
        ↓
relay release metadata + SLSA/CycloneDX verification
        ↓
strict Gradle dependency verification
        ↓
signed APK and AAB
        ↓
APK/AAB signature verification
        ↓
CycloneDX JSON SBOM
        ↓
SHA256SUMS verification
        ↓
SLSA provenance and CycloneDX attestations
        ↓
draft GitHub Release
        ↓
upload all four verified assets
        ↓
publish immutable stable release or prerelease
```

The final asset names are:

- `Symposium-<version>.apk`;
- `Symposium-<version>.aab`;
- `Symposium-<version>.cdx.json`;
- `SHA256SUMS`.

The release is created as a draft and is published only after all four exact
assets are present. Tags with a prerelease suffix are published as GitHub
prereleases. With immutable releases enabled, publication locks the tag and
assets.

The SBOM is generated by pinned Anchore/Syft from the final signed APK. A
CycloneDX Gradle integration was evaluated, but its build classpath conflicts
with the current Android Gradle Plugin over `commons-codec` and fails while
calculating SHA3-256 hashes. APK scanning is reliable for the shipped artifact,
but it can expose less Gradle configuration context than a release dependency
graph. This tradeoff should be reevaluated when either integration changes.

## Required GitHub secrets

- `ANDROID_KEYSTORE_BASE64`: base64-encoded release keystore;
- `ANDROID_KEYSTORE_PASSWORD`;
- `ANDROID_KEY_ALIAS`;
- `ANDROID_KEY_PASSWORD`;
- `TELEMETRY_ENDPOINT` (optional; blank disables telemetry);
- `TELEMETRY_TOKEN` (optional).

The keystore is reconstructed only under the ephemeral runner's temporary
directory and removed in an always-run cleanup step. The release build fails
instead of emitting official unsigned artifacts when any signing value is
missing. Telemetry values are not printed. Values embedded in an APK are
extractable and are not a strong secret boundary.

## Verify a published release

Download all assets into one directory, then verify checksums and signatures:

```bash
sha256sum --check SHA256SUMS
apksigner verify --verbose --print-certs Symposium-0.3.4.apk
jarsigner -verify -strict -verbose Symposium-0.3.4.aab
```

Verify GitHub SLSA provenance:

```bash
gh attestation verify Symposium-0.3.4.apk \
  -R decentral-prospect/symposium
gh attestation verify Symposium-0.3.4.aab \
  -R decentral-prospect/symposium
```

Verify the CycloneDX predicate bound to the APK:

```bash
gh attestation verify Symposium-0.3.4.apk \
  -R decentral-prospect/symposium \
  --predicate-type https://cyclonedx.org/bom
```

Auditors can independently inspect `relay.lock.json`, fetch its URL, compare the
SHA-256, and verify relay provenance against
`decentral-prospect/symposium-relay` using the same commands documented in
`BUILDING.md`.
